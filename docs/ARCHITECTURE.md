# 架构与职责

```text
控制机：labconsole网页 → 本机状态/方案/报告/历史回放/JSONL观察
                              ↑
                 独立只读采集器或未来算法遥测

待接入：平台设备库 → 角色/驱动初始化 → 绝对T0同步引擎 → 节点worker
```

网页只绑定127.0.0.1，写请求校验本机Host/Origin及令牌。离线执行在独立进程运行，SQLite持久记录和本机资源占用避免重复启动；不等于已有跨控制机节点锁。

Linux节点保留必要C命令程序和驱动，控制机不需要ath9k硬件。角色切换不需要每次重新编译驱动；新机器的首次匹配模块部署与日常组网是独立阶段。

以后分三层建模：稳定node_id/网卡radio_id；任务角色(AP/STA/监听/闲置)；本轮活跃发送集合。IP不是永久身份。新增设备不自动加入任务，使用中节点不可改连接信息或删除登记，移除登记不删除远端数据。

当前仍固定六角色、最多四业务STA，端口和参考引擎也有相应假设。任意规模、多个AP/BSS均未实现，不能仅增加配置行宣称扩容通过。

实时观察只接受遥测，未来算法用cw_requested/cw_applied/cw_verified记录意图和读回。实际控制事务、回退和动态实验方案尚未实现；不把实时图当固定CW正式样本。
