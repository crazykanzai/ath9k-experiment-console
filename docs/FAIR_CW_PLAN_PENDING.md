# 逐STA公平约束自动CW方案（保留，未实现）

2026-11-15：用户决定保留方案，暂停实现，先上传当前版本。本文不是已实现功能或新实验记录。

## 目标

有持续上传需求的STA间要求Jain>=0.90，且每台份额>=1/(2n)，四台时为12.5%。
在满足约束的配置中尽量提高聚合实收吞吐。这是有效评分区间的候选接受条件，
不承诺试探或环境突变时每秒公平。需求状态来自逐STA业务/队列，零接收不等于空闲；
不编码“人数->CW”。

## 最小实现

复用准备、采集、逐STA下发、绝对时间、20秒段/12秒评分、保持、恢复与手动接管。
仅新增公平评价、单STA邻居生成、约束与确认判断、页面公平指标/决策原因。
动作W8/16/32/64/128，每次只改变一台的一档CW，不扫描625种全组合，不做DQN。
公平不足时优先弱势节点减小W、强势节点增大W；达标后按封存轮换规则试探邻居。
每轮最多4个候选试探、2个确认，不宣称全局最优。

候选公平未达标即回退最后确认的可行配置并保留违规记录；
达标但吞吐改善不超过5%保持原配置；超过5%则先回参考配置再确认一次，确认通过才采用。
吞吐与公平稳定时保持；连续两有效段吞吐下降至少10%，或公平持续不达标，才有限重探。
无可行配置时报告目标未满足并停止搜索，不删低性能、不无限追加。
探索/回退/确认/违规时间全部计入整轮结果，手动接管保留。
