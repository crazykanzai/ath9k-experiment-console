随后按用户授权，将BE签名首次就绪宽限从80ms放宽到2000ms，使用非阻塞的本地绝对检查事件，窗口起止和每秒采样计划不变。待就绪的HoL/ACK为NA；就绪后仍核对CW与Basic签名，到期未就绪仍停止。worker记录statistics_policy及driver_signature_wait/ready事件。此更改仅针对初始化等待，不放宽已锁存配置不一致、FIFO、关联或恢复门禁；没有新硬件通过结论。

双击 `start_console.bat`，打开终端显示的本机网页。运行期间保留终端。新控制机首次使用先运行 `setup_console.bat`，核对平台档案和六节点SSH主机公钥。

1. 进入 **03 环境准备**。本台Windows若由W32Time占用UDP123，选择 **经AP有线中继**。输入凭据后依次点击连接设备、准备设备、同步时间并检查。授时配置完成后等待30秒并核验一次，通过后继续后台监测。
2. 准备就绪后点击 **进入现场演示**（或左侧 **04 现场自适应演示**），选择模式并点击 **启动所选演示**。
3. 选择 **手动切换**，初始W可选。启动后，在预热或等待T0时就可以提交下一个W。举例，初始W32，提交W64后看页面的下一段提示。第二段计划已发送后，可提交W32供第三段使用。切换指令提前4秒封存，已经封存的段保持原计划。
4. 选择 **自动调整** 时，业务以W128开始，随后探索W32、W64，并用已完成稳定段的聚合吞吐选择W。可另选 **固定CW对照** 执行相同时长的固定配置。自动演示结束时显示同轮基线、在线稳定段和含探索成本的全测量吞吐。
5. 可随时点击 **停止并恢复**。全部演示结束并确认恢复后，返回环境准备页点击 **结束使用并清理**。中断后重开同一工作区，通过环境准备页的中断恢复功能核对基线和清理时间覆盖。

现场演示运行在已有六角色平台，四STA使用Basic、24 Mbps、1200 B UDP、各30 Mbps、K3和FIFO20。手动为5/30/5秒，自动和固定为5/60/5秒。等待共同T0、采集回收和恢复另计。业务、CW与统计边界由节点本地执行，页面刷新只查询状态。共用绝对时间边界，每10秒一段，前3秒是切换保护期。全过程UDP吞吐保留，保护期及跨配置区间的HoL和ACK留空。

实时AP吞吐取自带内核时间戳的接收载荷，结束以AP抓包按控制机墙钟重分桶。实时HoL和ACK来自同驱动代次的完成计数差分。分段结算使用逐包完整服务集合，HoL为成功条件的主机服务起点代理。终态失败计入完整服务集合，分母未核准时ACK代理显示NA。短诊断有效性独立保存，正式窗口数始终为0。同轮阶段差会受外部占用和时间变化影响。

每次会话写入当前工作区的 `real_demos/<id>`，保存请求、硬件读回、节点事件、T0、原始JSON和pcap、追踪、指标及恢复回执。门禁失败停止并保留已经采集的证据。先处理故障和恢复，再由操作者决定是否启动新会话。

AP中继的控制机端只绑定有线UDP1123，AP临时占用其有线UDP123。中继只接收登记节点请求，由控制机生成时间戳，SSH租约结束后退出。结束清理恢复六节点的原时间配置。[时间中继方案](TIME_RELAY_PROPOSAL.md)
