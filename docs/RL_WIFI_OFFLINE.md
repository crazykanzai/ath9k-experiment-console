## RTT 与超时的口径

发送端按 `run_id/node_id/seq` 记录每个生成消息和发送结果。接收端仅返回短应用确认，
它不是 MAC ACK。UDP 请求总有效载荷1200 B，确认只有协议头42 B，不能把确认流量当作零。
RTT 从成功提交 socket 到收到首个匹配确认，使用发送端同一单调时钟，单位 ns。
截止期使用生成到首个确认的时间，包含提交前等待。它是“往返完成期限”，不是 AP 单向交付期限。
接收端无须向发送端提供可比较的时钟；共同 T0/采集对齐仍需既有时间同步。

分母为生成区间 `[start,end)` 中截止时刻已经到达的全部消息：

`mature = on_time + late + no_reply + local_failure + never_submitted`

`timeout_ratio = 1 - on_time / mature`；分母为空为 NA。
未到截止时刻的消息是 pending，不提前计为成功或失败；供算法的正式观测需完整成熟。
RTT 均值/P95 仅来自已回复消息，必须同时报告回复样本数、超时率和覆盖，不能拿其代表全部。
无回复但采集完整时，RTT 为 NA、超时率为1；网络输入保留显式“RTT已观测”掩码，
用高风险占位特征表达缺失，不把未知 RTT 当零。采集不完整则拒绝进入学习。
按发送端生成时刻划分 cohort，边界后等待一个 deadline；不能按回复时间换分母。

原语支持记录“计划产生”与实际唤醒时刻；调度漏掉的周期记为本地生成/调度失败，
不静默遗漏或密集补发。实机必须分别报告调度抖动，以免误归因无线问题。
`probe_transport.collect_sender` 逐事件回调日志 sink；调用方须创建独立日志、落盘并封存完成状态。
异常/中止不是完整运行；尚未成熟的分母不能用于奖励。原始 JSONL 使用新文件方式保存。

显式回放单个输入（示例数值对应合成输出）：

```powershell
python -m rl_wifi rtt-replay --input workspace/rl_offline_new/probe_events.jsonl --output workspace/probe_replay_new.json --start-ns 0 --end-ns 160000000 --as-of-ns 160000000
```

## 三个控制方法的共同契约

- 物理身份由未来场景清单指定；一个前景节点、显式背景集合，两组互斥，不能硬编码成IP。
- W分别取16/32/64，共9种组合；CWmin=W−1、CWmax=8W−1，K3、AIFSN3。
- 状态：前景/背景接收吞吐、条件RTT及观测掩码、超时率、两组当前W、业务活跃标记。
- 奖励：背景接收吞吐/固定参考吞吐 − 超时权重×超时率 − 切换权重×是否切换。
- 默认12Mbps/100ms/权重2和0.02仅供合成验证，不是已核准的实机参数。
- 固定策略：从开发种子选择，测试冻结。不是只和故意较差的W128对比。
- UCB：同九动作、滑动60段、探索系数0.25，奖励与其他策略一致；包括测试探索开销。
  这是新增共同动作空间对照，和旧网页三候选UCB不完全相同，不能混名。
- DQN：32/32隐藏层、经验回放、Huber损失、Adam、目标网络、折扣0.9、训练ε探索；
  测试冻结网络并关闭随机探索。保存源哈希和模型哈希。
- 观测缺失、NA、非有限数或invalid不生成假奖励，不写入训练回放。

合成环境刻意包含虚构的吞吐/期限权衡，只验证状态相关学习能否运行；
输出即使DQN不优于固定策略也完整报告，不调整测试数据制造改善。
五个模拟种子是软件测试 episode，不是实机五个独立重复。
本模块为独立实现，借鉴ReinWiFi研究思路；未迁移上游驱动或模型权重，不称完整复现。
