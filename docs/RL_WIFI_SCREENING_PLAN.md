# ReinWiFi 轻量适配：固定配置筛选方案（待确认，不执行）

版本：2026-11-14 / reinwifi-fixed-screen-v1。当前只完成专项门限调整、发生器离线验证和预登记。
**未连接节点、未启动新增业务。原 40 秒验收继续有效，原训练准备失败及零训练记录不改。**
原 5 训练＋15 对照窗口计划暂停，不随本方案自动恢复。方案确认后才准备独立筛选执行器，
不能把旧 live_learning 命令当成本方案执行入口；目前新增 screening_plan 命令只输出计划。

## 1. 要回答的问题与固定条件

检验“STA1 小 W、背景大 W 是否已经足够”，不预设需要强化学习。
只改变 STA1 的时间到达形态和两组 W；背景负载、平均前景负载及其余参数相同。
九动作是实时组/背景组 W∈{16,32,64} 的笛卡尔积，背景三台同 W。
包括 16/64 固定优先配置和 16/16、32/32、64/64；不额外增加 W8 或 W128。
W 表示窗口大小，CWmin=W−1、CWmax=8W−1，K3、BE AIFSN3。
Basic、DATA24Mbps、请求 UDP 载荷1200B、应用确认42B、FIFO20、原多段重试、
原位置/天线、原功率（须现场读回，原验收 STA14/AP16dBm）保持，不调包长/截止期寻找反转。
STA1 实时业务，STA2～4 各30Mbps/1200B背景，AP回复，MON15仅被动监听、有线管理。

## 2. 两种业务与发生器

| 状态 | 固定计划 | 长期平均 | 每个公共30秒 |
|---|---|---|---|
| U 均匀 | 从T0起每10ms计划1条 | 100条/秒，载荷0.96Mbps | 3000条 |
| B 突发 | 从T0起每100ms计划同时产生10条，序号独立 | 100条/秒，载荷0.96Mbps | 3000条 |

突发指周期性应用批次到达；同批十条的计划生成时刻及截止时刻相同，应用循环依次提交，
不人为为每条加入1ms间隔、不从实际完成时间漂移下一周期、不补发错过的历史批次。
两种状态都在整40秒运行，共4000条；周期相位相对共同T0固定，公共窗含300个突发批次。
1200B含协议头；42B是应用确认，不是802.11 ACK。100ms往返完成期限是本实验的工程目标，
不是Wi-Fi标准要求；在结果前固定“至少95%消息按时完成”（超时率≤5%）作为业务可行性目标。
该目标可能全部配置都达不到；届时报告本场景未满足目标，不降低门槛或修改负载。

两状态本地调度宽限均为10ms。处理某计划消息时延迟≥10ms，仍逐条记录计划/观察生成，
标 generator_missed_schedule，不向无线套接字追赶发送；暂时发送失败也逐条保留。
用预存的4000行计划（seq、计划墙钟/单调偏移、批次、截止期），与 generated/实际观察、
submitted、本地失败及 reply 事件核对。生成/提交/确认使用同一发送端单调时钟。
取消/门禁中止时尚未执行的计划是未执行/删失，不冒充无线丢失或完整窗口。

离线已验证：两状态消息数与公共窗数量相同；批次同刻；正常发送及回放；
延迟20ms不追赶首批；整个执行阻塞后全部计划逐条列本地失败；套接字满不缩小分母。
测试使用假时钟和假socket，不是Linux实机调度性能验收。目前该突发原语尚未部署，
旧实机节点入口仍只用原均匀参数；确认后才按封存计划接入，不能先试流调负载。

## 3. 固定规模、顺序和耗时

每窗5秒预热＋30秒唯一公共测量＋5秒收尾，配置在T0前设置并读回，整窗固定W。
所有六节点ready/armed后才选择至少未来20秒的共同绝对T0，采用本地调度；
不以逐台SSH到达启动。公共指标使用完整[T0+5,T0+35)，不删除切换/保护附近的差点。
原DCF统计段首3秒保护/签名降级只影响辅助HoL/概率，不能改变主要应用/背景指标的分母。

seed=2026111402，先随机九个动作，再随机每个动作相邻两种状态的先后。
相邻配对降低时间混杂，不能声称消除漂移。实际顺序封存在plan.json及SHA256：

| 窗口 | W实时/背景 | 状态顺序 |
|---|---|---|
| 1～2 | 64/16 | U，B |
| 3～4 | 32/16 | U，B |
| 5～6 | 32/64 | B，U |
| 7～8 | 64/32 | U，B |
| 9～10 | 32/32 | U，B |
| 11～12 | 16/32 | B，U |
| 13～14 | 16/64 | B，U |
| 15～16 | 64/64 | B，U |
| 17～18 | 16/16 | B，U |

初筛18窗只用于选候选，没有重复CI。仅在两状态选出不同配置，且第4节双向工程差异成立、
发生器质量通过时，才进入确认。候选集合为{U赢家、B赢家、16/64}去重，最多3个。
追加两个独立确认区组，每区组各候选×两状态各一次，最多12窗；
确认随机主序列也已在查看结果前封存，只按候选集合过滤，不重新抽签。
每条件最终有2个独立确认窗，初筛不混入确认均值/CI。绝不自动超过30窗、不替换失败窗。

18窗纯业务12分钟；30窗纯业务最多20分钟。每窗未来T0余量20秒另计，
预部署/配置/回收/校验估计30～60秒/窗，初筛含准备约30～45分钟，
最多30窗含确认/恢复约50～75分钟。它是时间估计，不是缩窗或跳门禁的理由。
主动执行预算：最多30个业务窗口、单窗业务40秒；总现场墙钟90分钟上限。
90分钟到期停止开始下一窗，已开始窗有界收尾/恢复；恢复不为赶时强杀。

## 4. 提前固定的选择与判定

只在同状态全部九个初筛结果完整时选配置；NA、未启动和门禁失败不补值。
无训练奖励拟合；筛选不使用原DQN奖励的权重来寻找有利结论。

1. 有超时率≤5%的配置：选背景接收吞吐最高者；位于最高值5%以内视为工程接近，
   从中选超时率最低者，再按条件RTT p95、更偏好16/64、动作索引破同值。
2. 全部不满足：先找最低超时率；最低值上方1个百分点以内选背景吞吐最高者，
   再按条件RTT p95、16/64、索引破同值。它仅是“失败中较好”，不叫满足实时要求。
3. 初筛触发确认还要求：U赢家在U相对B赢家，且B赢家在B相对U赢家，均满足以下之一：
   超时率降低至少5个百分点且背景吞吐下降不超过5%；或者二者均满足5%目标，
   背景吞吐提高至少5%且超时率恶化不超过1个百分点。
   一次初筛差异只是触发规则，不称显著，不因仅RTT更短而触发。

确认按窗口/区组为单位，列所有点和每条件n=2、t95%区间（df=1，t=12.706），
不以3000个包或每秒数据当独立重复。两区组各自算状态赢家相对另一赢家和16/64的差。
观察状态×动作交互：U下偏好a而B下偏好b；要求两个确认区组方向都重复，
其关键配对差的95%区间下限超过预登记工程差（超时5个百分点或背景5%），
同时保留对应的背景非劣/实时非劣约束。比较多个对手时作Holm校正，原始及校正结果都报。
小样本正态/独立假设未充分检验，即使通过也只称有限工程证据，不宣称论文级定论。

同时构造等权U/B的“已知状态选a/b”稳态参照与确认集合内每个固定配置比较：
T_D=(T_Ua+T_Bb)/2，B_D=(B_Ua+B_Bb)/2，逐区组配对，绝不在确认数据重新选a/b。
它是理想状态已知、未计切换的上界参照，不是已实施的在线算法。
九动作中未进确认集的固定配置只有一次初筛；不能声称已显著胜过九动作的最优固定值。

判定分三类：

- **存在值得研究的动态控制空间**：状态间权衡在独立确认中重复、差异超过上述波动与工程差，
  且各自选档满足实时目标；只能支持后续动态控制试验。若仅失败率间有可重复差异但均未达标，
  单列“状态依赖存在、实时目标未满足”，不叫已得到可用实时策略。
- **当前固定配置可优先使用**：同一配置在两状态都达到目标，确认数据的非劣区间能排除
  超时恶化>1个百分点及背景损失>5%，且动态稳态参照没有超过工程阈值的机会。
  此结论仅限所测条件/确认集合，不证明所有环境最优。
- **证据不足／当前场景尚未体现动态调节必要性**：初筛赢家相同、未出现双向工程差，
  差异未跨越波动、确认方向冲突、任一状态未达实时要求、发生器质量或采集不足。
  初筛相同且不启动确认时，可工程上先用固定配置，但不把“没显著差异”当等效性证明。

两个确认重复很容易得到宽区间，这是一种允许的最终结果，不追加到显著。

## 5. 采集、切换代价与门禁

应用超时分母为公共窗内全部已到截止时刻的**计划生成消息**；必须核对计划与观察生成，
迟到、最终未回复、本地失败、未提交均保留，不把成功子集当全体。
主指标T=1−100ms内确认数/成熟生成数；条件RTT为提交→确认的均值/p50/p95及回复样本数，
同时报告生成→确认时长、计划→实际生成延迟、本地失败分项。零回复时RTT为NA。
尾部至少100ms成熟；迟到/未回复的划分记录最终回收as_of，按时比例不因迟到而提高。
背景B为AP在同一公共绝对墙钟窗收到STA2～4的UDP载荷总量/30秒；另列每台和STA1接收量。
使用AP时钟偏差记录映射，给出边界敏感性（±包络），RTT不跨机器减时间戳。

应用账本/事件须回放一致、计划4000与公共3000核对、序号无无故缺失。
预登记发生器质量：公共窗本地失败≤1%，计划→实际生成延迟p99≤5ms。
超过时保留完整性能数据，标 application_inference_usable=false 并停止后续窗口；
它是主机到达形态不可信，不是无线性能差或抹去超时的理由，不补轮、调负载/周期重试。
离线调度测试只保证正确记账，现场是否达到此质量尚待本批真实窗口验证。

背景各STA每窗队列非空≥95%、积压(qdepth≥2或pending≥3)≥90%，STA1不要求饱和。
全部六节点源/同步/偏差/不确定度原始保存；专项首检包络≤50ms，(10,50]ms告警，
持续每10秒检查仍≤50ms，授时源和NTPSynchronized检查不取消。
边界要求100ms，包含所用时钟观测不确定度；共同T0和四STA切换/启动/停止硬件回执保留。
原共享锁、CW/AIFS/K3、FIFO20/零原生FIFO错误、模块/ABI、关联、进程/租约、
四类probe零miss/trace零overrun/drop，及抓包正常退出、kernel drop0/interface≤1%保持。
每个STA独立空口验证Basic（本STA RTS/CTS零）、已观测业务DATA24Mbps；
采集覆盖不足不得用其他STA代替。保留原监听Beacon/时间戳/帧完整性门禁和unknown，
不把“未捕获”叫“未发送”，不读clear-on-read MIB。
原演示统计签名降级规则仍只影响辅助HoL/概率NA，不降级上述硬件/追踪/应用门禁。

切换成本分三项报告：CW请求→各节点实际读回的延迟/离散度、驱动统计保护时间、
业务中切换的超时/吞吐损失。本轮固定窗只直接测第一项及窗间准备墙钟开销，
不把3秒统计保护等同3秒业务停顿；原40秒两个切换只能作历史诊断，不重跑。
第二项保留保护记录，第三项当前为**尚未识别**，不能从固定窗差推算实测净收益。
额外报告“每30秒一次切换、每次最多3秒零服务”的保守敏感性假设（10%服务预算）
及盈亏平衡可容忍开销；它不是测量值，也不据此调权重。
本轮若发现稳态机会，后续须独立验证实际在线切换和误判成本，才可说动态净收益成立。

窗口或准备门禁故障即保存、停止，不跳过或补测；低吞吐/高无线超时/自然MAC失败不删轮。
每窗正常/失败都恢复原有效CW/AIFS/override/Basic/速率/节能/功率、MON15原档案及关联，
仅清本次进程/monitor/追踪；恢复未确认则不开始下一窗。
一次准备可复用多窗，授时源持续运行；批次结束/故障恢复原时间配置并核对六节点和占用。
不重启、重载/部署驱动、改变持久配置、停原监控或擅自清理旧材料。

## 6. 如有机会，之后仍先比较简单方法

先检查能否在线观测业务状态：近期计划到达数/批次大小/间隔CV、队列增长、成熟消息超时率、
背景接收吞吐均为候选；不能把离线真实状态标签或未来回复泄露给控制器。
先做简单反馈规则，再谈DQN必要性。未来对照至少包含16/64固定优先、开发数据选出的强固定、
简单反馈规则、UCB、DQN，使用同九动作、同业务计划、同评价口径与预算。
独立开发/训练与留出测试；测试冻结DQN，保留探索/切换/错误选择/全部失误成本。
不要求DQN获胜，不追加到显著。这个方案只预留后续设计，本轮不执行任何算法训练或对照。
