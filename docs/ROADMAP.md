# 后续开发顺序

1. **可扩展设备库**：增加/编辑/禁用节点、凭据引用、真实接口发现；node_id/radio_id与角色分离。旧六角色导入提供版本迁移，不破坏回放。
2. **角色与组网**：有线SSH下分配AP/STA/监听/闲置，能力门禁、预览、备份、应用及有界回退；实验中禁止切角色。不需要节点旧页面。
3. **新机器初始化向导**：检查OS/内核/硬件和权限，选择经验证的驱动资源包，备份/安装/加载/验收/回退。无匹配包时进入独立构建，不假设同名ath9k即可复用。
4. **真实执行适配**：移除参考引擎的硬编码，接入平台档案/资源包/远端锁/持续时间流程/监听/显式窗口和恢复。先有界无业务验收、获准后短检，最后正式方案，不自动执行历史批次。
5. **任意节点规模**：动态端口、同步/采集/分析/图例和资源预算；逐规模验收，模板声明上限。
6. **动态CW与算法**：独立注册策略、请求/应用/读回证据、权限/事务/失败回退、变化区间与稳定期分析；不把动态段混入原固定CW重复。

这些是路线图，不是当前功能清单。每项通过离线和所需现场验收后再更新STATUS；不通过追改invalid或放宽门禁达成。
